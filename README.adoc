= EZGL - An Easy Graphics Library

image:https://codedocs.xyz/mariobadr/ezgl.svg[link="https://codedocs.xyz/mariobadr/ezgl"]

EZGL is a C++ graphics library that provides a thin wrapper around Qt 6,
making it easy to create GUI applications with 2D drawing support.
It is used by the https://github.com/verilog-to-routing/vtr-verilog-to-routing[VTR project] and as a teaching tool in ECE297.

Drawing goes through one of three interchangeable backends, all of which
render the same scene and differ only in how the primitives reach the screen:

* `immediate` paints every draw call straight away with QPainter.
* `deferred` records the draw calls and replays them in batches.
* `rhi` (the default) uploads geometry to the GPU through Qt's RHI.

A canvas picks one with `canvas::set_renderer_type()`; see
link:doc/renderers.md[doc/renderers.md] for the trade-offs, and the
`basic-application` example for a `--renderer` flag that switches between them.

== Dependencies

The library requires Qt 6.9.3 or newer: the Core, Gui, Widgets, Svg, and UiTools
modules, plus Qt's private GUI headers (`Qt6::GuiPrivate`), which is where the
QRhi classes used by the `rhi` backend live.

=== Build-tool dependency: Qt 6.9.3 + qtshadertools (provides `qsb`)

The RHI renderer's shaders are baked from GLSL to `.qsb` at build time.

  pip install aqtinstall==3.3.0
  aqt install-qt linux desktop 6.9.3 linux_gcc_64 -m qtshadertools --outputdir $HOME/qt6

== User interface forms

The window layout is described by a Qt Designer `.ui` file that EZGL loads at
run time, named by `application::settings::main_ui_resource`. Edit it in
`designer`.

=== EZGL widgets in a form

Some widgets cannot be written into the form directly:

* The canvas widget class depends on the renderer chosen when the application
  starts (see the table below). A `.ui` file names one fixed class, so it
  cannot pick the right one in advance.
* Qt Designer, and the `QUiLoader` that builds the window from the form, only
  create Qt's own widget classes; EZGL registers no Designer plugins for its
  own. So EZGL's `DrawingAreaWidget` and `SwitchButton` cannot be named there.
* A popup panel needs a popup window flag and a link to the button that opens
  it. A form can store neither.

So the form declares a placeholder widget and marks it with a tag, and EZGL
creates or sets up the real widget right after loading the form. A tag is a dynamic
property: add it in Designer's Property Editor with *+ > String...* (the `.ui`
file records it as `stdset="0"`).

`ezglWidgetClass`:: Set on a plain `QWidget` placeholder that EZGL replaces
with its own widget. The tag value names the widget; for the canvas, the widget
EZGL creates also depends on the renderer, set with `canvas::set_renderer_type`
before the window is built:
+
[cols="1,2,1",options="header"]
|===
| Tag value | Renderer | Widget created
| `DrawingAreaWidget` | `immediate` | `DrawingAreaWidget`
| `DrawingAreaWidget` | `deferred` | `DrawingAreaWidget`
| `DrawingAreaWidget` | `rhi`, or not set (the default) | `RhiCanvasWidget`
| `SwitchButton` | any | `SwitchButton`
|===

`ezglPopupFor`:: Set on a panel to make it a popup opened by a button. The
value is that button's `objectName`.

Every EZGL form must also contain a `QMainWindow`, a canvas placeholder, and a
`QStatusBar` named `StatusBar`.

== Compilation

This project uses CMake for compiling and requires CMake version 3.10 or higher.
CMake can configure the project for different build systems and IDEs (type `cmake --help` for a list of generators available for your platform).
We recommend you create a build directory before invoking CMake to configure the project (`cmake -B`).
For example, we can perform the configuration step from the project root directory:

  cmake -H. -Bcmake-build-release -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=$HOME/qt6/6.9.3/gcc_64
  cmake -H. -Bcmake-build-debug -DCMAKE_BUILD_TYPE=Debug -DCMAKE_PREFIX_PATH=$HOME/qt6/6.9.3/gcc_64

After the configuration step, you can ask CMake to build the project.

  cmake --build cmake-build-release/ --target all
  cmake --build cmake-build-debug/ --target all

=== Build Options

Build options can be found in `options.cmake`.
Simply specify the build option during the configuration step in CMake.
Using the already generated `cmake-build-release` directory from the previous section, we can:

  cmake -H. -Bcmake-build-release -DEZGL_BUILD_EXAMPLES=ON -DCMAKE_PREFIX_PATH=$HOME/qt6/6.9.3/gcc_64

Your IDE or Makefile should now include additional targets when you turn these options on.
For example, enabling `EZGL_BUILD_EXAMPLES` should provide access to the `basic-application` target, which you can build:

  cmake --build cmake-build-release/ --target basic-application
